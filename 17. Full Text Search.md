# 1. Full-Text Search

> É um método rápido para encontrar palavras ou frases dentro de grandes coleções de textos ou bancos de dados.

- Usado para pesquisas inteligentes em grandes volumes de texto.
    
- Em vez de verificar cada caractere de cada documento, o sistema cria um índice antecipado para encontrar os termos de forma rápida e relevante.
    
- Utiliza um índice criado especificamente para pesquisas textuais.
    
- Pode ordenar os resultados por relevância.
    
- É mais adequado para pesquisas textuais do que `LIKE`.
    
- Evita, em muitos casos, a necessidade de realizar um `Table Scan`.
    

### 1.1 Criação do índice

No MySQL, podemos criar um índice Full-Text:

```sql
CREATE FULLTEXT INDEX idx_content
ON documents(content);
```

### 1.2 Realizando a pesquisa

A pesquisa pode ser feita utilizando `MATCH` e `AGAINST`:

```sql
SELECT *
FROM documents
WHERE MATCH(content) AGAINST(?);
```

- `MATCH` indica a coluna que será pesquisada.
    
- `AGAINST` recebe o termo que será pesquisado.
    
- O Full-Text Search pode utilizar a relevância para determinar quais resultados são mais importantes.
    

### 1.3 Modos de pesquisa

O Full-Text Search pode possuir diferentes modos de pesquisa.

- **Natural Language Mode:** interpreta a pesquisa de maneira mais natural e considera a relevância dos termos.
    
- Pode possuir recursos como **sinônimos**, dependendo do banco e da configuração utilizada.
    
- Pode ignorar palavras consideradas pouco relevantes, chamadas de **stop words**.
    

### 1.4 Full-Text Search x `LIKE`

O `LIKE` procura uma sequência de caracteres dentro do texto.

Por exemplo:

```sql
WHERE nome LIKE '%ana%'
```

Pode retornar:

```text
Ana
Luciana
Adriana
Mariana
```

Isso acontece porque `ana` aparece dentro de todas essas palavras.

- `LIKE` é útil para buscas simples por padrões.
    
- Full-Text Search é mais adequado quando queremos encontrar **termos relevantes dentro de textos**.
    
- Em grandes tabelas, pesquisas como `LIKE '%termo%'` podem resultar em **Table Scan**, sendo pouco performáticas.
    

### 1.5 Table Scan

> Table Scan ocorre quando o banco precisa percorrer as linhas de uma tabela para encontrar os registros que correspondem à consulta.

- Pode ser pouco performático em tabelas grandes.
    
- Pesquisas textuais com `LIKE '%termo%'` podem causar esse comportamento.
    
- Um índice Full-Text permite ao banco consultar uma estrutura criada especificamente para a busca.

# 2. Funcionamento por baixo dos panos

> O Full-Text Search processa previamente os textos e cria uma estrutura de índice que relaciona os termos encontrados aos documentos onde eles aparecem.

### 2.1 Tokenização

> Tokenização é o processo de dividir um texto em partes menores, normalmente palavras chamadas de **tokens**.

Por exemplo:

```text
"Banco de dados é muito importante"
```

Pode ser dividido em:

```text
Banco
de
dados
é
muito
importante
```

### 2.2 Remoção de palavras irrelevantes

> Durante o processamento, o sistema pode remover palavras que possuem pouca relevância para a pesquisa.

Exemplo:

```text
de
a
o
e
para
com
```

Essas palavras são chamadas de **stop words**.

- Reduzem o tamanho do índice.
    
- Evitam armazenar termos que normalmente não ajudam na busca.
    
- As palavras consideradas irrelevantes dependem do banco e da configuração.
    

### 2.3 Índice invertido

> O índice invertido mapeia cada palavra diretamente para os documentos ou posições onde ela aparece, evitando que o banco precise ler cada documento para encontrar o termo.

Em vez de:

```text
Documento → palavras
```

o índice funciona aproximadamente como:

```text
Palavra → documentos onde aparece
```

Exemplo:

```text
"banco"     → documento 1, 5, 8
"postgres"  → documento 2, 5
"sql"       → documento 1, 2, 5
```

Assim, ao pesquisar:

```text
postgres
```

o sistema pode consultar diretamente os documentos relacionados ao termo.
### 2.4 GIN Index no PostgreSQL

> O **GIN (Generalized Inverted Index)** é um tipo de índice do PostgreSQL adequado para estruturas em que um termo pode estar relacionado a vários documentos ou registros. Ele permite localizar rapidamente os registros que contêm determinados termos.

- É muito utilizado com **Full-Text Search** no PostgreSQL.
    
- Funciona sobre uma estrutura semelhante a um **índice invertido**.
    
- Relaciona os termos encontrados aos registros onde eles aparecem.
    
- Evita que o banco precise percorrer todos os registros para encontrar determinado termo.
    

### 2.5 Lexemas

> **Lexema** é a forma normalizada de uma palavra utilizada pelo PostgreSQL durante o processamento do Full-Text Search.

Por exemplo, dependendo da configuração de idioma e do processamento aplicado, diferentes formas de uma palavra podem ser reduzidas a uma representação comum.

O PostgreSQL utiliza o `to_tsvector()` para transformar um texto em uma estrutura contendo os **lexemas** e suas informações.

Exemplo:

```sql
SELECT to_tsvector('portuguese', 'O banco de dados possui bancos modernos');
```

O resultado é uma representação dos termos relevantes do texto, podendo conter informações como:

```text
'banc':1,6 'dad':3 'modern':7
```

- Os termos são transformados em **lexemas**.
    
- Palavras irrelevantes podem ser removidas.
    
- As posições dos termos no texto podem ser armazenadas.
    
- O `tsvector` é a representação utilizada pelo PostgreSQL para realizar a busca textual.
    

### 2.6 Fluxo do Full-Text Search

```text
Texto
  ↓
Tokenização
  ↓
Remoção de stop words
  ↓
Normalização
  ↓
Lexemas
  ↓
Índice invertido / GIN
  ↓
Pesquisa
  ↓
Resultados relevantes
```
