# 12. Stored Procedures

## 12.1 O que são

Stored Procedures são **programas armazenados dentro do banco de dados**.

Elas permitem agrupar vários comandos SQL em uma única rotina que pode ser executada quando necessário.

Em vez de enviar vários comandos:

```sql
INSERT ...
UPDATE ...
SELECT ...
```

podemos colocar esses comandos dentro de uma Procedure e chamá-la:

```sql
CALL minha_procedure();
```

### Exemplo simples

Imagine um sistema financeiro que precisa registrar uma transferência.

Sem Procedure:

```text
1. Retirar dinheiro da conta A
2. Adicionar dinheiro na conta B
3. Registrar a transferência
```

Com uma Procedure:

```sql
CALL realizar_transferencia(1, 2, 5000);
```

A Procedure pode executar os três passos.

### Onde isso aparece na vida real?

- Processamento de pagamentos
    
- Fechamento financeiro
    
- Geração de relatórios
    
- Atualização de dados relacionados
    
- Processamentos internos do banco
    
- Rotinas administrativas
    

---

## 12.2 Criando uma Procedure

Estrutura básica no MySQL:

```sql
DELIMITER //

CREATE PROCEDURE nome_da_procedure()
BEGIN
    -- comandos SQL
END //

DELIMITER ;
```

Exemplo:

```sql
CREATE PROCEDURE listar_clientes()
BEGIN
    SELECT *
    FROM clients;
END;
```

A Procedure acima simplesmente consulta os clientes.

---

## 12.3 Chamando uma Procedure

Para executar:

```sql
CALL listar_clientes();
```

Uma vantagem é poder executar vários comandos com apenas um `CALL`.

Exemplo:

```sql
CALL realizar_transferencia(1, 2, 5000);
```

---

## 12.4 Parâmetros

Uma Procedure pode receber informações para utilizar durante sua execução.

### IN

`IN` representa um parâmetro de **entrada**.

É o caso mais comum.

```sql
CREATE PROCEDURE buscar_cliente(IN cliente_id INT)
BEGIN
    SELECT *
    FROM clients
    WHERE id = cliente_id;
END;
```

Chamando:

```sql
CALL buscar_cliente(10);
```

Nesse caso:

```text
10 → entra na Procedure → usado no SELECT
```

### Exemplo real

Uma aplicação pode enviar:

```text
clienteId = 10
```

e a Procedure busca os dados daquele cliente.

---

### OUT

`OUT` permite que a Procedure **devolva um valor através de um parâmetro**.

Exemplo:

```sql
CREATE PROCEDURE contar_clientes(OUT quantidade INT)
BEGIN
    SELECT COUNT(*)
    INTO quantidade
    FROM clients;
END;
```

Chamando:

```sql
CALL contar_clientes(@total);
```

Depois:

```sql
SELECT @total;
```

Resultado:

```text
150
```

### Exemplo real

Pode ser utilizado para retornar informações como:

```text
Quantidade de clientes
Quantidade de pedidos
Total de vendas
Saldo calculado
```

---

### INOUT

`INOUT` permite que o parâmetro:

1. entre na Procedure;
    
2. seja alterado;
    
3. saia com o novo valor.
    

Exemplo:

```sql
CREATE PROCEDURE adicionar_bonus(INOUT valor INT)
BEGIN
    SET valor = valor + 100;
END;
```

Chamando:

```sql
SET @valor = 500;

CALL adicionar_bonus(@valor);

SELECT @valor;
```

Resultado:

```text
600
```

---

## 12.5 Variáveis

Dentro de uma Procedure podemos utilizar variáveis para guardar valores temporariamente.

### DECLARE

Variáveis locais são declaradas com `DECLARE`.

```sql
DECLARE total INT;
```

Depois podemos atribuir um valor:

```sql
SET total = 100;
```

Ou:

```sql
SET total = total + 50;
```

### Importante: `@variavel`

No MySQL existem dois conceitos diferentes:

**Variável local:**

```sql
DECLARE total INT;
```

**Variável de usuário/sessão:**

```sql
SET @total = 100;
```

O `@` **não é obrigatório para todas as variáveis**.

Dentro de uma Procedure, normalmente utilizamos `DECLARE` para variáveis locais.

---

### Recebendo resultado de SELECT

Podemos colocar o resultado de um `SELECT` dentro de uma variável:

```sql
DECLARE quantidade INT;

SELECT COUNT(*)
INTO quantidade
FROM clients;
```

Agora:

```text
quantidade
    ↓
150
```

Podemos utilizar essa variável posteriormente na Procedure.

---

## 12.6 DELIMITER

O `DELIMITER` é utilizado para informar ao cliente SQL que o `;` dentro da Procedure **não representa o final da Procedure inteira**.

Por exemplo:

```sql
DELIMITER //

CREATE PROCEDURE exemplo()
BEGIN
    SELECT 1;
    SELECT 2;
END //

DELIMITER ;
```

Sem alterar o delimiter, o cliente poderia interpretar:

```sql
SELECT 1;
```

como o fim do comando.

### Importante

`DELIMITER` não é exatamente uma instrução da Procedure.

Ele é uma configuração utilizada pelo cliente/ferramenta SQL para conseguir enviar a Procedure inteira ao banco.

---

## 12.7 DEFINER

`DEFINER` indica **qual usuário do banco é considerado o definidor da Procedure**.

Exemplo:

```sql
CREATE DEFINER='admin'@'localhost'
PROCEDURE listar_clientes()
BEGIN
    SELECT *
    FROM clients;
END;
```

Isso pode ser importante principalmente em questões de:

- permissões;
    
- segurança;
    
- execução da Procedure;
    
- migração entre ambientes.
    

Por isso, ao exportar ou importar Procedures, é comum encontrar:

```sql
DEFINER
```

---

## 12.8 Listando Procedures

No MySQL podemos consultar as Procedures existentes:

```sql
SHOW PROCEDURE STATUS;
```

Também podemos filtrar:

```sql
SHOW PROCEDURE STATUS
WHERE Db = 'meu_banco';
```

Isso é útil para descobrir quais Procedures existem no banco.

---

## 12.9 Alterando e removendo Procedures

### Remover

Para remover uma Procedure:

```sql
DROP PROCEDURE nome_da_procedure;
```

É comum utilizar:

```sql
DROP PROCEDURE IF EXISTS nome_da_procedure;
```

Assim evitamos erro caso ela não exista.

### Alterar

No MySQL, a alteração de uma Procedure é mais limitada do que simplesmente editar seu código.

Na prática, é comum:

```sql
DROP PROCEDURE IF EXISTS minha_procedure;

CREATE PROCEDURE minha_procedure()
BEGIN
    ...
END;
```

# 12.10 Cursores

Um Cursor permite percorrer **linha por linha** o resultado de uma consulta dentro de uma rotina armazenada.

Uma forma simples de imaginar:

```text
SELECT retorna:

João
Maria
Pedro
Carlos

Cursor:

→ João
→ Maria
→ Pedro
→ Carlos
```

Ele é útil quando precisamos executar algum processamento individual para cada linha.

### Importante

Cursor **não é um vetor**.

Ele funciona mais como um mecanismo para percorrer um conjunto de resultados, normalmente uma linha por vez.

---

## DECLARE CURSOR

Exemplo conceitual:

```sql
DECLARE cursor_clientes CURSOR FOR
    SELECT id, name
    FROM clients;
```

Esse Cursor representa o resultado da consulta.

Depois podemos utilizar:

```sql
FETCH
```

para buscar a próxima linha.

---

## Exemplo simples

Imagine que precisamos percorrer todos os clientes para executar algum processamento.

```text
Clientes

1 - João
2 - Maria
3 - Pedro
```

O Cursor pode fazer:

```text
1. Busca João
2. Processa João

3. Busca Maria
4. Processa Maria

5. Busca Pedro
6. Processa Pedro
```

Esse tipo de processamento pode ser útil quando cada registro precisa de uma lógica individual.

---

## Quando usar Cursor?

Exemplo de uma rotina administrativa:

```text
Para cada cliente:

    verificar alguma condição

    se necessário:
        atualizar cliente

    continuar para o próximo
```

Isso pode ser feito com Cursor.

Porém, **Cursor não deve ser a primeira opção para tudo**.

Quando conseguimos resolver o problema com um único comando SQL, geralmente é melhor.

Por exemplo:

```sql
UPDATE clients
SET status = 'INACTIVE'
WHERE last_login < '2025-01-01';
```

é normalmente melhor do que:

```text
pegar cliente
→ verificar
→ atualizar
→ pegar próximo
→ verificar
→ atualizar
→ ...
```
