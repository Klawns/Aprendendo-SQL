# 1. Introdução aos JOINs

> **JOIN** é uma operação utilizada para combinar registros de duas ou mais tabelas em uma única consulta.

Para que um JOIN funcione, as tabelas devem possuir algum relacionamento, normalmente por meio de **chaves primárias (PK)** e **chaves estrangeiras (FK)**.

- Permite criar consultas mais completas.
    
- Conecta registros de tabelas relacionadas.
    
- Baseia-se na **Teoria dos Conjuntos**.
    
- O tipo de JOIN determina quais registros serão retornados.
    

### Principais tipos

- **INNER JOIN**
    
- **LEFT JOIN**
    
- **RIGHT JOIN**
    
- **FULL OUTER JOIN**
    

---

# 2. LEFT JOIN


> O **LEFT JOIN** retorna **todos os registros da tabela da esquerda** e apenas os registros correspondentes da tabela da direita.

Caso não exista correspondência, os campos da tabela da direita são preenchidos com **NULL**.

- Retorna todos os registros da tabela da esquerda.
    
- Retorna apenas os registros relacionados da tabela da direita.
    
- Registros sem correspondência recebem `NULL`.

## Sintaxe

```sql
SELECT *
FROM tabela_esquerda
LEFT JOIN tabela_direita
ON tabela_esquerda.id = tabela_direita.fk_tabela_esquerda_id;
```
## Exemplo

Tabelas:

**CLIENTE**

|id|nome|
|--:|---|
|1|João|
|2|Maria|
|3|Pedro|

**PEDIDO**

|id|cliente_id|
|--:|--:|
|1|1|
|2|2|

Consulta:

```sql
SELECT c.nome, p.id
FROM cliente c
LEFT JOIN pedido p
ON c.id = p.cliente_id;
```

Resultado:

|Cliente|Pedido|
|---|--:|
|João|1|
|Maria|2|
|Pedro|NULL|

# 3. RIGHT JOIN

> O **RIGHT JOIN** retorna **todos os registros da tabela da direita** e apenas os registros correspondentes da tabela da esquerda.

- Caso não exista correspondência, os campos da tabela da esquerda são preenchidos com **NULL**.

- Retorna todos os registros da tabela da direita.
    
- Retorna apenas os registros relacionados da tabela da esquerda.
    
- Registros sem correspondência recebem `NULL`.
    
- Produz o mesmo resultado de um **LEFT JOIN** com a ordem das tabelas invertida.
    

## Sintaxe

```sql
SELECT *
FROM tabela_esquerda
RIGHT JOIN tabela_direita
ON tabela_esquerda.id = tabela_direita.fk_tabela_esquerda_id;
```

## Exemplo

Consulta:

```sql
SELECT
    c.nome,
    p.id_pedido
FROM cliente c
RIGHT JOIN pedido p
ON c.id_cliente = p.id_cliente;
```

Resultado:

| Cliente | Pedido |
| ------- | -----: |
| João    |    101 |
| Maria   |    102 |
| NULL    |    103 |

O pedido **103** não possui um cliente correspondente, por isso os campos da tabela **CLIENTE** são preenchidos com `NULL`.

# 4. INNER JOIN

> O **INNER JOIN** retorna **apenas os registros que possuem correspondência entre as duas tabelas**.

- Retorna somente os registros relacionados.
    
- Registros sem correspondência **não** aparecem no resultado.
    
- Não retorna `NULL` por falta de relacionamento.
    
- É o tipo de JOIN mais utilizado.
    
## Sintaxe

```sql
SELECT *
FROM tabela_esquerda
INNER JOIN tabela_direita
ON tabela_esquerda.id = tabela_direita.fk_tabela_esquerda_id;
```

## Exemplo

Consulta:

```sql
SELECT
    c.nome,
    p.id_pedido
FROM cliente c
INNER JOIN pedido p
ON c.id_cliente = p.id_cliente;
```

Resultado:

|Cliente|Pedido|
|---|--:|
|João|101|
|Maria|102|

O cliente que não possui pedido e o pedido que não possui cliente **não aparecem** no resultado, pois o **INNER JOIN** retorna apenas os registros que possuem correspondência entre as tabelas.

# 5. UNION e UNION ALL

> Os operadores **UNION** e **UNION ALL** são utilizados para **unir o resultado de duas ou mais consultas** em um único conjunto de resultados.

- Unem o resultado de consultas diferentes.
    
- As consultas devem possuir o **mesmo número de colunas**.
    
- As colunas devem estar **na mesma ordem**.
    
- Os tipos de dados das colunas devem ser compatíveis.
    
- **UNION** remove registros duplicados (`DISTINCT`).
    
- **UNION ALL** mantém todos os registros, inclusive os duplicados.
    
## Sintaxe

```sql
SELECT <projeção>
FROM <tabela>

UNION / UNION ALL

SELECT <projeção>
FROM <tabela>

ORDER BY <colunas>;
```

Também é possível unir mais de duas consultas:

```sql
SELECT <projeção> FROM <tabela>

UNION / UNION ALL

SELECT <projeção> FROM <tabela>

UNION / UNION ALL

SELECT <projeção> FROM <tabela>

ORDER BY <colunas>;
```

## Exemplo

```sql
SELECT 'morango' AS fruta
UNION
SELECT 'uva' AS fruta
UNION ALL
SELECT 'morango' AS fruta;
```

Resultado:

|fruta|
|---|
|morango|
|uva|
|morango|

O valor **"morango"** aparece duas vezes.

Isso acontece porque o SQL avalia a consulta **de cima para baixo**. Primeiro o `UNION` elimina os registros duplicados entre as duas primeiras consultas. Em seguida, o `UNION ALL` apenas adiciona o último resultado, sem verificar duplicidades.
## Diferença entre UNION e UNION ALL

|UNION|UNION ALL|
|---|---|
|Remove registros duplicados (`DISTINCT`).|Mantém todos os registros.|
|Pode ser mais lento devido à remoção de duplicados.|Geralmente é mais rápido.|
|Usado quando não se deseja repetição de dados.|Usado quando as duplicatas devem ser preservadas.|

# 6. FULL OUTER JOIN

> O **FULL OUTER JOIN** retorna **todos os registros das duas tabelas**, relacionados ou não.

- Retorna todos os registros da tabela da esquerda.
    
- Retorna todos os registros da tabela da direita.
    
- Quando não existe correspondência, os campos da outra tabela são preenchidos com `NULL`.
    
- Equivale à união dos resultados de um **LEFT JOIN** e um **RIGHT JOIN**.
    

> **Observação:** o **MySQL** não possui suporte nativo ao `FULL OUTER JOIN`.

## Sintaxe

```sql
SELECT *
FROM tabela_esquerda
FULL OUTER JOIN tabela_direita
ON tabela_esquerda.id = tabela_direita.fk_tabela_esquerda_id;
```

## Como fazer no MySQL

Como o MySQL não implementa `FULL OUTER JOIN`, utiliza-se a união de um `LEFT JOIN` com um `RIGHT JOIN`:

```sql
SELECT *
FROM tabela_esquerda
LEFT JOIN tabela_direita
ON tabela_esquerda.id = tabela_direita.fk_tabela_esquerda_id

UNION

SELECT *
FROM tabela_esquerda
RIGHT JOIN tabela_direita
ON tabela_esquerda.id = tabela_direita.fk_tabela_esquerda_id;
```


## Exemplo

Consulta (MySQL):

```sql
SELECT
    c.nome,
    p.id_pedido
FROM cliente c
LEFT JOIN pedido p
ON c.id_cliente = p.id_cliente

UNION

SELECT
    c.nome,
    p.id_pedido
FROM cliente c
RIGHT JOIN pedido p
ON c.id_cliente = p.id_cliente;
```

Resultado:

|Cliente|Pedido|
|---|--:|
|João|101|
|Maria|102|
|Pedro|NULL|
|NULL|103|

O cliente **Pedro** aparece mesmo sem pedido, e o pedido **103** aparece mesmo sem cliente.
