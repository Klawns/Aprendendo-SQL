# Views

> Uma **View** é uma consulta SQL salva que pode ser utilizada como se fosse uma tabela. Ela é útil para esconder consultas complexas e facilitar o acesso aos dados.

## 1. View

> Uma View tradicional é uma espécie de **tabela virtual** criada a partir de um `SELECT`. Ela não precisa armazenar os dados fisicamente; quando consultada, normalmente executa a consulta que foi definida nela.

- Pode reunir informações de várias tabelas.
    
- Pode ser utilizada em outros `SELECT`.
    
- Pode ser utilizada em `JOIN` com outras tabelas ou Views.
    
- Ajuda a reutilizar consultas complexas.
    
- Encapsula a lógica de uma consulta, deixando o código que a utiliza mais simples.
    
- A View pode continuar mostrando dados atualizados das tabelas utilizadas na consulta.
    

### 1.1 Criação de uma View

```sql
CREATE VIEW <vw_nomeView> AS
SELECT (...);
```

**Exemplo:**

```sql
CREATE VIEW vw_clientes_ativos AS
SELECT id, nome, email
FROM clientes
WHERE ativo = true;
```

Depois disso, podemos consultar a View como se fosse uma tabela:

```sql
SELECT *
FROM vw_clientes_ativos;
```

### 1.2 View utilizando várias tabelas

Uma View pode esconder uma consulta que utiliza várias tabelas.

```sql
CREATE VIEW vw_pedidos_clientes AS
SELECT
    p.id AS pedido_id,
    c.nome AS cliente,
    p.valor
FROM pedidos p
JOIN clientes c ON c.id = p.cliente_id;
```

Assim, em vez de repetir esse `JOIN` sempre que precisarmos dessas informações, podemos simplesmente fazer:

```sql
SELECT *
FROM vw_pedidos_clientes;
```

### 1.3 Utilizando View com `JOIN`

Como uma View pode ser consultada como uma tabela, também podemos fazer `JOIN` com ela:

```sql
SELECT *
FROM vw_pedidos_clientes v
JOIN pagamentos p
    ON p.pedido_id = v.pedido_id;
```

### 1.4 Alterando uma View

Podemos alterar a consulta utilizada pela View usando `ALTER VIEW`, dependendo do banco de dados.

```sql
ALTER VIEW vw_clientes_ativos AS
SELECT id, nome
FROM clientes
WHERE ativo = true;
```

> A sintaxe exata pode variar dependendo do SGBD utilizado.

### 1.5 Excluindo uma View

Para remover uma View:

```sql
DROP VIEW vw_clientes_ativos;
```

## 2. View Materializada

> Uma **View Materializada** é diferente de uma View tradicional porque ela **armazena fisicamente o resultado da consulta**. Isso permite que consultas posteriores sejam mais rápidas, pois o banco não precisa executar toda a consulta complexa novamente.

- É útil para consultas complexas e pesadas.
    
- O resultado da consulta fica armazenado.
    
- Pode melhorar bastante a performance das consultas.
    
- Os dados armazenados precisam ser atualizados.
    
- É muito utilizada quando os dados não precisam estar atualizados a cada segundo.
    

### 2.1 View tradicional × View materializada

**View tradicional:**

```text
SELECT
    ↓
Executa a consulta
    ↓
Busca os dados nas tabelas
    ↓
Retorna o resultado
```

**View materializada:**

```text
SELECT
    ↓
Processa a consulta
    ↓
Armazena o resultado
    ↓
Consulta posterior
    ↓
Lê o resultado já armazenado
```

> Por isso, uma View Materializada pode ser mais rápida para consultas pesadas, mas precisa de uma estratégia para atualizar seus dados.

### 2.2 Exemplo de uso

Imagine uma consulta que precisa juntar milhões de registros para gerar um relatório.

Em vez de executar essa consulta pesada toda vez que alguém abrir o relatório, podemos:

1. Executar o processamento durante a madrugada.
    
2. Armazenar o resultado.
    
3. Durante o dia, os usuários consultam os dados já processados.
    
4. Atualizar os dados novamente durante a madrugada.
    

Isso troca **tempo de processamento no momento da consulta** por **processamento antecipado**.

### 2.3 View Materializada com atualização

Uma View Materializada pode ser atualizada de acordo com o SGBD utilizado.

No PostgreSQL, por exemplo:

```sql
REFRESH MATERIALIZED VIEW nome_da_view;
```

Assim, o banco executa novamente a consulta e atualiza os dados armazenados.

## 3. View e Performance

> Views não são automaticamente mais rápidas. Uma View tradicional serve principalmente para **organização, reutilização e simplificação de consultas**.

- Uma View tradicional normalmente executa sua consulta quando é acessada.
    
- Se a consulta por trás da View for muito complexa, ela pode continuar sendo pesada.
    
- Uma View Materializada pode melhorar a performance porque mantém o resultado armazenado.
    
- É necessário analisar o custo de atualização da View Materializada.
    
- O uso de Views deve ser planejado de acordo com a necessidade da aplicação.
